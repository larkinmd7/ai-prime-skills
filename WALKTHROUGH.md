# Полный путь: от папки с кодом до сайта в интернете

Шесть шагов. На каждом — промпт, который просто копируете агенту.

---

## Перед началом

| Что | Проверка |
|---|---|
| Скиллы установлены | в папке проекта: `.claude/skills/` или `.agents/skills/` |
| Ключ Timeweb в `.env` | файл `.env` создан из `.env.example` |
| Баланс Timeweb | не меньше 1 500 ₽ |
| Docker Desktop запущен | значок кита в строке меню |
| Имя домена придумано | и есть пара запасных вариантов |

Если чего-то не хватает, начните с этого промпта:

```
Проверь, установлены ли Git, GitHub CLI и Docker.
Чего нет — установи. Потом авторизуй меня в GitHub
через gh auth login и покажи, под каким аккаунтом я вошёл.
```

### Где взять ключ Timeweb

1. Открыть **timeweb.cloud/my/api-keys** — в панели это вкладка
   **«API и Terraform»**.
2. Кнопка **«Добавить токен»**. Имя — любое, чтобы отличать.
   Срок действия — **«Бессрочно»**.
3. Нажать **«Выпустить»**. Появится длинная строка, начинается на `eyJ`.
4. Скопировать её в файл `.env`, в строку `TIMEWEB_CLOUD_TOKEN=`.

⚠️ Токен показывается **один раз**. Закрыли окно — посмотреть повторно
нельзя, только выпустить заново на той же странице.

### Как пустить агента в GitHub

Отдельный ключ не нужен — агент авторизуется через браузер:

```
Авторизуй меня в GitHub через gh auth login.
Покажи мне код, который надо ввести в браузере,
и скажи, под каким аккаунтом я в итоге вошёл.
```

В терминале появится код вида `XXXX-XXXX`, откроется страница
**github.com/login/device** — вставьте код и подтвердите.

На вопросы отвечайте: **GitHub.com** → **HTTPS** → **Yes** →
**Login with a web browser**.

## Шаг 1 · Упаковать приложение

```
Упакуй это приложение в Docker и запусти у меня на компьютере.
Проверь, что оно открывается в браузере, и дай мне адрес.
```

**Что произойдёт:** агент разберётся, на чём написано приложение,
напишет инструкцию сборки, соберёт образ и запустит.

**Как понять, что получилось:** приложение открывается на `localhost`
и работает так же, как раньше.

---

## Шаг 2 · Положить код на GitHub

```
Создай приватный репозиторий на GitHub и закинь туда код.
Перед этим убедись, что мои ключи и пароли туда не попадут.
Дай мне ссылку на репозиторий.
```

**Что произойдёт:** агент сначала закроет секреты от публикации,
проверит это командой, и только потом создаст репозиторий.

**Как понять, что получилось:** ссылка открывается, код внутри,
файла `.env` там нет.

⚠️ Если агент попросит авторизоваться — в терминале появится
восьмизначный код, откроется браузер. Вставьте код и подтвердите.

---

## Шаг 3 · Проверить деньги

```
Покажи мой баланс в Timeweb и какие есть тарифы серверов.
```

**Зачем:** пополнить баланс через агента невозможно — только руками
в панели. Лучше узнать сейчас, чем упереться на середине.

---

## Шаг 4 · Домен и сервер

```
Проверь, свободен ли домен МОЙ-ДОМЕН.ru.
Если свободен — покажи цену и жди моего подтверждения,
потом зарегистрируй его.
Ещё арендуй сервер с 4 ГБ памяти в России.
```

**Что произойдёт:** агент покажет цены и **остановится**.
Дальше пойдёт только после вашего «да».

**Сколько ждать:** сервер поднимается за полторы-две минуты.

⚠️ **Домен заработает не сразу** — адрес расходится по интернету
от получаса до нескольких часов. Это нормально, так устроен интернет.

---

## Шаг 5 · Опубликовать

```
Задеплой приложение из моего GitHub-репозитория на арендованный сервер.
Настрой HTTPS-сертификат, направь на него мой домен
и проверь, что сайт открывается. Покажи ссылку.
```

**Что произойдёт:** агент зайдёт на сервер, поставит всё нужное,
заберёт код из репозитория, запустит приложение и выпустит сертификат.

**Как понять, что получилось:** откройте ссылку **на телефоне**.
Открылось на телефоне — значит работает для всех, а не только у вас.

---

## Шаг 6 · Тестовый стенд

Нужен, когда появятся пользователи: чтобы обновлять сайт,
не ломая его для людей.

```
Создай второй стенд на том же сервере: dev.МОЙ-ДОМЕН.ru.
Туда пусть едет ветка dev, а на основной адрес — ветка main.
Закрой dev-стенд паролем.
```

**Как этим пользоваться дальше:**

```
правка → отправил в ветку dev → посмотрел на dev.сайт.ru
       → всё хорошо → слил в main → пользователи получили
```

Одним промптом:

```
Отправь эту правку на dev-стенд.
```

Проверили — и:

```
Всё хорошо, выкати на основной сайт.
```

---

## Дальше

Продукт живёт в интернете и работает без вашего компьютера.
Чтобы обновить — правите у себя и повторяете шаг 6.
Ничего заново настраивать не нужно.

---

## Если что-то пошло не так

**Сайт не открывается, а сервер работает.**
Скорее всего, домен ещё не разошёлся. Подождите час и проверьте снова.
Спросите агента: `проверь, куда сейчас указывает мой домен`.

**Агент говорит, что не хватает денег.**
Пополните баланс в панели Timeweb. Через агента это сделать нельзя.

**Сборка падает на сервере.**
Не хватает памяти. Попросите: `добавь на сервер swap` — или возьмите
тариф побольше.

**Что-то сломалось после обновления.**
```
Верни предыдущую рабочую версию сайта.
```

**Сервер больше не нужен.**
```
Удали сервер и покажи, сколько я теперь трачу в месяц.
```
⚠️ Остановленный сервер продолжает тарифицироваться. Не нужен — удаляйте.
