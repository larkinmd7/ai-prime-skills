# Упаковка приложения в Docker

Задача скилла: превратить папку с кодом в образ, который одинаково
запускается на любом компьютере и на сервере.

## Главное правило

Пользователь — не программист. Он хочет, чтобы работало.
Не объясняй устройство Docker, если не спросили. Сделай и покажи результат.

Одна метафора, если нужно объяснить: **образ — это рецепт, контейнер —
блюдо по нему.** Рецепт можно переслать, и на другом компьютере получится
ровно то же самое.

---

## Порядок работы

### 1. Понять, что за приложение

Прочитай папку. Определи:

- язык и версию (`package.json`, `requirements.txt`, `go.mod`, `composer.json`);
- как запускается (`npm start`, `python app.py`, бинарник);
- какой порт слушает;
- нужны ли внешние программы (`ffmpeg`, `imagemagick`);
- нужна ли база данных;
- какие переменные окружения читает.

**Если в проекте уже есть `Dockerfile` — не переписывай его.** Прочитай,
объясни пользователю в двух предложениях, что он делает, и собирай по нему.

### 2. Написать Dockerfile

Правила, которые соблюдай всегда:

1. **Официальный базовый образ**, версия зафиксирована: `python:3.12-slim`,
   `node:22-slim`, `golang:1.24-bookworm`. Никогда `latest`.
2. **Многостадийная сборка**, если есть этап сборки. В финальный образ
   попадает только результат, без компиляторов и инструментов.
3. **Сначала зависимости, потом код.** Копируй `package.json` /
   `requirements.txt` и ставь зависимости **до** копирования остального кода.
   Иначе каждая правка кода заново качает все библиотеки.
4. **Non-root пользователь** в финальном образе.
5. **`EXPOSE`** с портом приложения.
6. **`HEALTHCHECK`**, если у приложения есть endpoint проверки.
7. **Комментарии по-русски** — пользователь должен понимать, что читает.

### 3. Написать .dockerignore

Обязательно. Без него в образ уедет мусор и, что хуже, секреты.

Минимум: `.git`, `.env`, `node_modules`, `__pycache__`, `venv`, `*.log`,
`.DS_Store`, папки сборки.

### 4. Собрать и проверить

```bash
docker build -t <имя> .
docker run --rm -p <порт>:<порт> <имя>
```

**Проверка обязательна**: открой приложение и убедись, что оно отвечает.
Не говори «готово», пока не увидел ответ.

```bash
curl -sS -o /dev/null -w '%{http_code}' http://localhost:<порт>
```

### 5. Показать результат

Скажи пользователю:

- по какому адресу открыть;
- размер образа (`docker images`);
- сколько заняла сборка.

## Если нужна база данных

Одного контейнера мало — пиши `compose.yml`:

```yaml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    env_file: .env
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - dbdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

volumes:
  dbdata: {}
```

Запуск: `docker compose up -d`, логи: `docker compose logs -f`.

## Постоянные данные

Всё, что должно пережить перезапуск — база, загруженные файлы,
скачанные модели — выноси в **том**:

```yaml
volumes:
  - appdata:/app/data
```

Без тома данные сотрутся при первом же обновлении приложения.
Объясни это пользователю одной фразой: «образ — это программа,
том — ваши данные, они остаются при обновлении».

---

## Секреты

- **Никогда** не вписывай ключи и пароли в `Dockerfile` или `compose.yml`.
- Секреты приходят через `env_file: .env` или переменные окружения.
- `.env` обязан быть в `.dockerignore` и в `.gitignore`.
- Не печатай значения ключей в вывод.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Сборка идёт очень долго каждый раз | код копируется до установки зависимостей — переставь местами |
| `docker: command not found` | Docker Desktop не установлен или не запущен |
| Контейнер стартует и сразу падает | смотри `docker logs <id>`; обычно не хватает переменной окружения |
| Приложение не открывается в браузере | внутри контейнера слушает `127.0.0.1` вместо `0.0.0.0` |
| Образ весит гигабайты | нет многостадийной сборки или `.dockerignore` |
| Данные пропали после обновления | не подключён том |
| На Mac M-серии не собирается | добавь `--platform linux/amd64`, если целевой сервер x86 |

---

## Чего не делать

- Не ставить `latest` у базового образа.
- Не запускать от root в финальном образе.
- Не копировать `.env` внутрь образа.
- Не говорить «готово», не проверив, что приложение отвечает.
- Не переписывать чужой рабочий `Dockerfile` без просьбы.
