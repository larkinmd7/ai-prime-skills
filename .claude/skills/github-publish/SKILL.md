# Публикация кода на GitHub

Задача скилла: положить код в репозиторий так, чтобы его можно было
забрать на сервер и в любой момент вернуться к прошлой версии.

## Главное правило

Пользователь — не программист. Не объясняй устройство Git, если не спросили.
Делай и показывай ссылку на результат.

Если объяснение всё же нужно, одной фразой: **коммит — это сохранение
с подписью, что и зачем поменяли.** GitHub — копия этих сохранений
в интернете, откуда их заберёт сервер.

---

## ⛔ Железное правило: .gitignore ДО первого коммита

**Секреты проверяются раньше, чем создаётся репозиторий.** Не наоборот.

Причина: `.gitignore` не действует на файлы, которые уже попали
в репозиторий. Если `.env` уехал в первый коммит, вычистить его
из истории тяжело, а ключи к этому моменту уже скомпрометированы.

Порядок обязательный:

1. Создать `.gitignore`.
2. Проверить: `git check-ignore .env` — должен вернуть путь.
3. Только потом `git init`, `git add`, `git commit`.

Если проверка не прошла — **остановись и скажи пользователю**.
Не создавай репозиторий.

### Что всегда в .gitignore

```gitignore
# секреты
.env
.env.*
!.env.example
*.pem
*.key
credentials.json

# зависимости
node_modules/
venv/
__pycache__/
.venv/

# сборка
dist/
build/
*.log

# система
.DS_Store
Thumbs.db
```

## Порядок работы

### 1. Проверить доступ

```bash
git --version
gh --version
gh auth status
```

Чего нет — поставь. Если `gh` не авторизован:

```bash
gh auth login
```

⚠️ **Этот шаг пользователь проходит сам**: агент запускает команду,
в терминале появляется восьмизначный код, открывается браузер.
Код надо вставить в браузере и подтвердить. Объясни это заранее,
одной фразой, без подробностей.

### 2. Подготовить репозиторий

```bash
git init -b main
# .gitignore уже создан и проверен — см. правило выше
git add <конкретные файлы>
git commit -m "Первая версия"
```

### 3. Создать на GitHub и запушить

**По умолчанию — приватный репозиторий.** Публичный только если
пользователь явно попросил.

```bash
gh repo create <имя> --private --source=. --remote=origin --push
```

### 4. Показать результат

Дай ссылку на репозиторий и скажи, что внутри.
**Проверь глазами**, что `.env` туда не попал:

```bash
git ls-files | grep -E '^\.env$' && echo "ОПАСНОСТЬ: .env в репозитории"
```

## Что коммитить

Указывай **конкретные файлы**, а не `git add -A` и не имя папки.

Причина: `git add -A` втягивает всё подряд, включая случайные файлы,
которые пользователь не собирался публиковать. Папка в `git add` —
то же самое, только замаскированное.

Перед коммитом посмотри, что попадёт:

```bash
git status --short
git diff --cached --name-only
```

## Вернуться к прошлой версии

Это то, ради чего всё затевалось. Три сценария:

**Посмотреть историю:**

```bash
git log --oneline -10
```

**Вернуть один файл как было:**

```bash
git checkout <коммит> -- путь/к/файлу
```

**Отменить последние изменения, сохранив историю:**

```bash
git revert <коммит>
```

⚠️ **Никогда не делай `reset --hard` и `push --force`** без явного
разрешения пользователя. Это стирает работу безвозвратно.

## Ветки dev и main

Нужны, когда у продукта появились пользователи.

| Ветка | Что там | Куда едет |
|---|---|---|
| `main` | только проверенное | рабочий сайт |
| `dev` | что угодно, можно ломать | тестовый стенд |

```bash
git checkout -b dev        # создать
git push -u origin dev     # опубликовать
```

Цикл обновления: правка в `dev` → проверил на тестовом стенде →
слил в `main` → пользователи получили.

```bash
git checkout main
git merge dev
git push
```

## Секреты для деплоя

Если сервер должен сам забирать код — ему нужны доступы.
Они кладутся в настройки репозитория, **не в код**:

```bash
gh secret set ИМЯ --body "$ЗНАЧЕНИЕ_ИЗ_ENV"
gh secret set SSH_KEY < ~/.ssh/id_ed25519_deploy
```

Значения берутся из `.env` и **никогда не печатаются** в вывод,
логи или переписку.

## Частые проблемы

| Симптом | Решение |
|---|---|
| `gh: not logged in` | `gh auth login`, код вводится в браузере |
| Просит логин и пароль при push | нужен `gh auth login`, пароли GitHub отключил |
| `.env` попал в репозиторий | `git rm --cached .env`, добавить в `.gitignore`, **сменить все ключи** |
| `repository already exists` | имя занято, взять другое |
| Двухфакторка не пускает | нужен телефон с приложением-аутентификатором |
| Случайно закоммитил лишнее | `git reset HEAD~1` до push; после push — `git revert` |

---

## Чего не делать

- Не создавать репозиторий, пока не проверен `.gitignore`.
- Не делать `git add -A` и не указывать папку целиком.
- Не делать `push --force` и `reset --hard` без разрешения.
- Не создавать публичный репозиторий по умолчанию.
- Не печатать значения секретов.
- Не удалять репозиторий без отдельного подтверждения.
